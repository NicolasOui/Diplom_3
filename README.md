# Автоматизация UI-тестов для сервиса Stellar Burgers

UI-тесты для фронтенда веб-приложения **Stellar Burgers**.

Используется паттерн **Page Object Model (POM)** с интеграцией UI и API, чтобы ускорить подготовку окружения, + поддерживается кроссбраузерное тестирование.

## 🛠 Стек технологий
* **Язык программирования:** Java 11 (Amazon Corretto JDK)
* **Тестовый фреймворк:** JUnit 4.13.2
* **Автоматизация UI:** Selenium WebDriver 4.28.0 (Chromium)
* **Подготовка данных (API):** RestAssured 5.4.0 + Gson 2.10.1 (для ручной сериализации)
* **Генерация данных:** DataFaker 1.9.0 (генератор реалистичных сущностей)
* **Библиотека проверок:** AssertJ 3.24.2
* **Отчетность:** Allure 2.25.0 + AspectJ Weaver 1.9.22
* **Система сборки:** Maven

## 📂 Структура проекта

* `src/main/java/pages/` — Page Objects (классы `MainPage` и `LoginPage` с локаторами и методами взаимодействия).
* `src/main/java/api/` — API-клиенты и константы (`CreateUserSteps` с сериализацией через Gson, `Endpoints`).
* `src/test/java/helper/` — Вспомогательные тестовые инструменты (`RandomDataUser` для генерации уникальных профилей через DataFaker).
* `src/test/java/tests/` — Тестовые классы (`BaseTest` с кроссбраузерной логикой, `ConstructorTest`, `LoginTest`, `MainLoginPageTest`).

## 🚀 Покрытие тест-кейсов (9 сценариев)

1. **Регистрация пользователя (`MainLoginPageTest`)**
    * Успешная регистрация с валидными динамическими данными от DataFaker.
    * Проверка вывода ошибки при вводе пароля менее 6 символов.
2. **Авторизация пользователя (`LoginTest`)**
    * Вход по центральной кнопке «Войти в аккаунт» на главной.
    * Вход через верхнюю кнопку «Личный кабинет».
    * Вход через ссылку «Войти` на форме регистрации.
    * Вход через ссылку «Войти` на форме восстановления пароля.
      *(Данные пользователей в этих тестах создаются мгновенно через API в `@Before` и удаляются в `@After`).*
3. **Раздел «Конструктор» (`ConstructorTest`)**
    * Переход к разделу «Булки».
    * Переход к разделу «Соусы».
    * Переход к разделу «Начинки».

## 💻 Инструкция по запуску

### 1. Подготовка окружения
* По умолчанию тесты настроены на запуск в браузере **Google Chrome** (локальный драйвер не требуется, Selenium 4 скачивает его автоматически).
* Для запуска в **Яндекс.Браузере** в папке `drivers/` должен лежать `yandexdriver.exe`, версия которого строго соответствует версии установленного в системе Яндекс.Браузера.

### 2. Запуск тестов через Maven
Запуск выполняется из корневой папки проекта через терминал.
* **Запуск в Google Chrome (по умолчанию):**
  ```bash
  mvn clean test
  ```

* **Запуск в Яндекс.Браузере:**
  ```bash
  mvn clean test -Dbrowser=yandex
  ```

### 3. Генерация и просмотр отчетов Allure
После завершения тестирования можно собрать все файлы в HTML-отчёт:
* **Через плагин Maven:**
  ```bash
  mvn allure:serve
  ```
* **Через установленный в систему Allure CLI:**
  ```bash
  allure serve target/allure-results
  ```
